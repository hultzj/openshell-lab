= 模块 6：凭据安全
:navtitle: 模块 6：凭据安全

为代理提供 API 密钥的常见方式是使用环境变量，而这样一来，代理就可以打印、记录或发送该密钥。本模块回答：**代理能否看到我们的 LLM 密钥？它所持有的东西是否值得窃取？**

您将在沙箱内查找密钥，通过边界使用占位符，然后尝试从外部使用同一个占位符。

.初次接触边界凭据解析？
[%collapsible]
====
* *提供程序（provider）* — OpenShell 中的一条记录，保存某个上游服务（此处为 MaaS）的凭据。
* *解析器令牌* — 沙箱看到的占位符 `openshell:resolve:env:…`，用来代替密钥。
* *边界* — 监管程序的出站代理，它会在被允许的请求上将占位符替换为密钥。
====

== 技术背景

[cols="1,3",options="header"]
|===
| 阶段 | 密钥所在位置

| 安装
| Helm 值被写入 Vault（`secret/hub/infra/openshell/maas`）和 Secret `maas-api-key`
| 设置
| 设置 Job 将该密钥作为 `maas` 提供程序的凭据注册到网关
| 运行时
| 沙箱只获得解析器令牌；监管程序将密钥附加到发往 `{maas_host}` 的请求上
|===

== 学习目标

* 证明沙箱环境中不存在任何形式的真实密钥。
* 证明占位符通过边界可以正常使用，而在其他任何地方都会失败。

== 练习 1：在沙箱内查找密钥

[source,bash,role="execute",subs="attributes+"]
----
openshell sandbox exec {sandbox_name} < /dev/null -- bash -c 'env | grep -i maas; env | grep -c "sk-"'
----

预期结果: 一行 `MAAS_API_KEY=openshell:resolve:env:v…_MAAS_API_KEY`，以及计数 `0`：沙箱环境中任何地方都没有
`sk-` 值。

== 练习 2：通过边界使用占位符

[source,bash,role="execute",subs="attributes+"]
----
openshell sandbox exec {sandbox_name} < /dev/null -- bash -c 'curl -s -o /dev/null -w "MaaS HTTP %\{http_code}\n" --max-time 5 https://{maas_host}/v1/models -H "Authorization: Bearer $MAAS_API_KEY"'
----

预期结果: `MaaS HTTP 200`。请求离开沙箱时携带的是占位符，而 MaaS 收到的是真实密钥。

== 练习 3：在其他地方尝试使用占位符

NOTE: 两次尝试都会失败。这是预期行为：这正是窃取了占位符的攻击者会尝试的操作。

首先，从沙箱内部针对另一个 API 进行尝试：

[source,bash,role="execute",subs="attributes+"]
----
openshell sandbox exec {sandbox_name} < /dev/null -- bash -c 'curl -sS --max-time 5 https://api.openai.com/v1/models -H "Authorization: Bearer $MAAS_API_KEY"; echo "exit=$?"'
----

预期结果: `curl: (7) Failed to connect to api.openai.com` 和 `exit=7`：对于允许列表之外的主机，占位符永远不会离开沙箱。

然后，将占位符从沙箱中复制出来，并在边界之外，直接从您的 Web Terminal 将其发送到 MaaS：

[source,bash,role="execute",subs="attributes+"]
----
TOKEN=$(openshell sandbox exec {sandbox_name} < /dev/null -- printenv MAAS_API_KEY 2>/dev/null | grep '^openshell:resolve')
echo "stolen: ${TOKEN:0:30}..."
curl -s -w "\nHTTP %\{http_code}\n" --max-time 10 https://{maas_host}/v1/models -H "Authorization: Bearer $TOKEN" | tail -c 160
----

预期结果: `stolen: openshell:resolve:env:v…`，然后是一个 `auth_error`，指出密钥 `expected to start
with 'sk-'`，以及 `HTTP 401`。在练习 2 中获得 `HTTP 200` 的同一个字符串，在这里毫无价值。

简而言之：代理只能将密钥用于其所绑定的那一个服务，而且只能在沙箱内部使用。

== 证据检查点

* 在此集群上，还有谁能读取真实密钥？为什么这是可以接受的？
* 除了占位符之外，攻击者还需要什么才能使用该密钥？

.答案
[%collapsible]
====
* 集群管理员，他们可以从 Vault 或 Secret `maas-api-key` 中读取（模块 7 会读取其前几个字符）。边界保护密钥免受代理的访问，而不是免受平台管理员的访问。
* 需要在此沙箱内运行的代码，并通过监管程序调用 MaaS 主机；仅有占位符什么也做不了。
====
