= 架构与控制边界
:navtitle: 架构与控制边界

本页不包含命令。它说明各个组件如何协同工作，以便您理解后续的每一个结果。

== 控制问题

每个模块都会用您亲自收集的证据回答以下问题之一：

* *代理能否向我们未批准的主机发送数据？*（模块 4）
* *代理能否读取或更改其工作目录之外的文件，即使以 root 身份运行？*（模块 5）
* *代理能否看到、打印或泄露我们的 LLM API 密钥？*（模块 6）
* *密钥保存在哪里、由谁同步、工作负载如何被识别？*（模块 7）
* *能否要求使用真实的用户身份来访问网关？*（模块 8）
* *能否在不重新部署代理的情况下更改它可以访问的内容？*（模块 9）

== 技术栈

|===
| 层 | 组件 | 职责

| 平台

| ZTVP

| ZTVP

| 对用户进行身份验证，并为网关客户端颁发 OIDC 令牌

| 应用
| OpenShell 网关 (`openshell-system`)
| 供 CLI 使用的 gRPC API；管理沙箱、提供程序（provider）和策略

| 应用
| OpenShell 监管程序（supervisor）
| 在代理的进程树之外运行；强制执行网络边界，并将解析器令牌替换为真实凭据

| Pi 代理运行所在的容器，受网络策略和 Landlock 策略约束

== 需要理解的一个关键区别

Kubernetes NetworkPolicy 决定哪些 *pod* 可以与哪些地址通信。OpenShell 网络策略则决定
*沙箱内的哪个程序* 可以访问哪个 *主机名*：`curl` 可以调用 MaaS API，`npm` 可以调用 npm 注册表，其他任何程序都无法访问任何地方。沙箱会把每个未列出的主机解析为一个占位地址，并由监管程序拒绝连接，因此被拒绝的调用会在几毫秒内失败，而不是等待超时。

凭据的工作方式与此相同。在沙箱内部，`MAAS_API_KEY` 是一个解析器令牌。只有位于代理接触范围之外的监管程序才会将其替换为真实密钥，而且只针对发往该提供程序所绑定端点的请求进行替换。

请求路径如下：

[cols="1,3",options="header"]
|===
| 跳 | 发生的事情

| 1. CLI → 网关 Service
| `openshell sandbox exec` 通过 HTTPS 将 gRPC 请求发送到网关的集群内 Service（没有公共 Route；NetworkPolicy 只允许实验命名空间和 Web Terminal 命名空间访问）
| 2. 网关
| 网关找到沙箱并转发命令
| 3. 网关 → 监管程序 → 沙箱
| 监管程序在应用策略的情况下，在沙箱内运行该命令
| 4. 沙箱 → 边界
| 每个出站连接都会根据主机和二进制文件允许列表进行检查
| 5. 边界 → MaaS
| 对于被允许的 MaaS 调用，解析器令牌会被替换为来自 Vault 的真实密钥
|===

== 实验流程

=== 1. 从目录部署 OpenShell
注册 Chart 仓库，使用您的 MaaS 密钥安装发行版本，并观察各个钩子（hook）向 Vault 写入初始数据、创建沙箱并注册 Keycloak 客户端。

=== 2. 连接 OpenShell CLI
将 CLI 指向网关 Service，列出沙箱，并确认集群外部无人能够访问网关。

=== 3. 使用 Pi 进行 AI 代理编码
让 Pi 编写一个脚本和一个小型 REST API，然后在沙箱内运行它们。

=== 4. 网络零信任
调用允许的主机和未列出的主机，并比较结果和耗时。

=== 5. 文件系统零信任
在策略允许的位置写入，然后尝试写入 `/etc`、`/usr` 和 `/`。

=== 6. 凭据安全
在沙箱内打印密钥，通过边界使用它，然后尝试将它用于另一个端点。

=== 7. ZTVP 集成
读取由 Vault 支持的 ExternalSecret、ClusterSPIFFEID、ACS Central 以及 Keycloak 客户端。

=== 8. 用户身份验证
创建一个 Keycloak 用户，为网关客户端请求令牌并解码其声明（claim）。

=== 9. 动态策略
在正在运行的沙箱上允许 `pypi.org`，证明其生效，然后撤销。

== 结果解读注意事项

* 本实验只展示一个沙箱和一个策略。它不衡量边界带来的开销，也不衡量边界在负载下的表现。
* 演示网关接受未经身份验证的 CLI 调用，以便实验能够快速开始。模块 8 展示 OIDC 的配置方式，而不是一个会拒绝匿名调用方的网关。
* 沙箱以 pod 的形式运行在集群上；容器逃逸不在本实验的测试范围之内。
* OpenShell、Pi 代理镜像和演示 Chart 均为上游和社区组件，而不是红帽支持的产品。请参阅
  xref:91-reference.adoc[技术参考]。
