自律型の AI コーディングエージェントを OpenShift 上で実行し、そのエージェントに何ができないかを検証します。

link:https://pi.dev/[Pi^] などの AI コーディングエージェントは、コードの作成、パッケージのインストール、API の呼び出し、プログラムの実行を自律的に行います。そのため、制約のないエージェントは、ソースコードを任意のサーバーに送信したり、コンテナー内の任意のファイルを読み取ったり、与えられた LLM API キーを漏えいさせたりする可能性があります。このラボでは、Red Hat Zero Trust Validated Pattern (ZTVP) がすでに稼働しているクラスター上の NVIDIA OpenShell サンドボックス内で
Pi エージェントを実行し、各制限を鵜呑みにするのではなく、ご自身で検証していただきます。

このラボは次のタスクの順に進みます。

. OpenShell の Helm チャートを Developer Catalog に登録してインストールします。API キーは Vault に格納し、パブリックエンドポイントは公開しません。
. OpenShell CLI をゲートウェイに接続します。
. Pi が Red Hat MaaS の LLM を介してコードを作成し、実行する様子を確認します。
. サンドボックスが承認済みの 3 つのホストにしか到達できないことを検証します。
. Linux カーネル (Landlock) によって、エージェントが書き込めるパスが制限されることを検証します。
. 実際の API キーがサンドボックスに入らないことを検証します。
. Vault、External Secrets、SPIRE、ACS、Keycloak が OpenShell にどのように組み込まれているかをたどります。
. ゲートウェイの OIDC クライアント用の Keycloak トークンを取得します。
. 実行中のサンドボックスのネットワークポリシーを変更し、その変更を取り消します。

== 学習目標

このラボを終えると、次のことができるようになります。

* Developer Catalog に登録された Helm チャートリポジトリーから、クラスター内部からのみ到達可能な形で OpenShell を OpenShift にデプロイする。
* エージェントサンドボックスからの送信 (egress) が許可される場合と拒否される場合を実証し、拒否が即座に行われる理由を説明する。
* root ユーザーであれば通常は書き込めるパスも含め、コンテナー内での Landlock によるファイルシステムの制御を実証する。
* リゾルバートークンによって、実際の LLM 認証情報がサンドボックスの外に保たれる仕組みを説明する。
* チャートが構成する Vault パス、ExternalSecret、ClusterSPIFFEID、Keycloak クライアントの場所を特定する。
* サンドボックスのネットワークポリシーをライブで更新して変更を検証し、その後元に戻す。

== 技術モデル

* *OpenShift* はすべてのコンポーネントを実行し、Developer Catalog、Route、Web Terminal を提供します。
* *ZTVP* は共有セキュリティーサービスを提供します。Vault（シークレット）、External Secrets Operator（シークレットの同期）、Keycloak（ユーザー ID）、SPIFFE/SPIRE（ワークロード ID）、Advanced Cluster Security（イメージおよびランタイムポリシー）です。
* *OpenShell* は、ゲートウェイ、エージェントとネットワークの間に位置するスーパーバイザー、およびポリシーエンジンを追加します。
* *Landlock* は Linux カーネルのセキュリティーモジュールで、サンドボックスのファイルシステムポリシーを適用します。
* *Pi* はテスト対象のエージェントで、*Red Hat MaaS* (Model-as-a-Service) はエージェントが呼び出す LLM です。

単一のレイヤーだけでは十分ではありません。Kubernetes の NetworkPolicy はプロセス単位ではなく Pod 単位で機能します。Vault はシークレットを暗号化して保持しますが、読み取りを許可された相手には誰にでもそれを渡します。コンテナーのファイルシステムは root に対して何も制限しません。OpenShell のバイナリー単位の送信ルール、Landlock、そして境界側での認証情報の解決がこれらのギャップを埋め、ZTVP が OpenShell の利用する ID とシークレットを提供します。
