= アーキテクチャーと制御境界
:navtitle: アーキテクチャーと制御境界

このページにはコマンドはありません。各要素がどのように組み合わさっているかを説明し、以降のすべての結果を理解できるようにします。

== 制御に関する問い

各モジュールでは、ご自身で収集した証拠をもとに、次のいずれかの問いに答えます。

* *エージェントは、承認していないホストにデータを送信できるか?*（モジュール 4）
* *エージェントは、root であっても、作業ディレクトリーの外にあるファイルを読み取ったり変更したりできるか?*（モジュール 5）
* *エージェントは、LLM API キーを参照、出力、または漏えいさせることができるか?*（モジュール 6）
* *キーはどこに保管され、誰が同期し、ワークロードはどのように識別されるか?*（モジュール 7）
* *ゲートウェイへのアクセスに、実際のユーザー ID を必須にできるか?*（モジュール 8）
* *エージェントを再デプロイせずに、エージェントが到達できる範囲を変更できるか?*（モジュール 9）

== 理解すべき唯一の違い

Kubernetes の NetworkPolicy は、どの *Pod* がどのアドレスと通信できるかを決定します。OpenShell のネットワークポリシーは、*サンドボックス内のどのプログラム* がどの *ホスト名* に到達できるかを決定します。たとえば、`curl` は
MaaS API を呼び出すことができ、`npm` は npm レジストリーを呼び出すことができ、それ以外は何にも到達できません。サンドボックスはリストにないすべてのホストをプレースホルダーアドレスに名前解決し、スーパーバイザーがその接続を拒否します。そのため、拒否された呼び出しはタイムアウトを待つのではなく、ミリ秒単位で失敗します。

認証情報も同じように機能します。サンドボックス内では、`MAAS_API_KEY` はリゾルバートークンです。エージェントの手が届かない場所にあるスーパーバイザーだけが、それを実際のキーに置き換えます。しかも、プロバイダーがバインドされているエンドポイントへのリクエストに対してのみです。

リクエストの経路は次のとおりです。

[cols="1,3",options="header"]
|===
| ホップ | 処理内容

| 1. CLI → ゲートウェイ Service
| `openshell sandbox exec` が、HTTPS 上の gRPC でゲートウェイのクラスター内 Service にリクエストを送信します（パブリック Route はなく、NetworkPolicy によってラボと Web Terminal の namespace からの通信のみが許可されます）
| 2. ゲートウェイ
| ゲートウェイがサンドボックスを特定し、コマンドを転送します
| 3. ゲートウェイ → スーパーバイザー → サンドボックス
| スーパーバイザーが、ポリシーを適用した状態でサンドボックス内でコマンドを実行します
| 4. サンドボックス → 境界
| すべての送信接続が、ホストとバイナリーの許可リストに照らしてチェックされます
| 5. 境界 → MaaS
| 許可された MaaS 呼び出しでは、リゾルバートークンが Vault から取得した実際のキーに置き換えられます
|===

== ラボの流れ

=== 1. カタログから OpenShell をデプロイする
チャートリポジトリーを登録し、MaaS キーを指定してリリースをインストールします。その後、フックによって Vault にシードが投入され、サンドボックスが作成され、Keycloak クライアントが登録される様子を確認します。

=== 2. OpenShell CLI を接続する
CLI がゲートウェイ Service を参照するように設定し、サンドボックスを一覧表示して、外部の誰もゲートウェイに到達できないことを確認します。

=== 3. Pi による AI エージェントコーディング
Pi にスクリプトと小さな REST API の作成を依頼し、それらをサンドボックス内で実行します。

=== 4. ネットワークのゼロトラスト
許可されたホストとリストにないホストを呼び出し、結果と所要時間を比較します。

=== 5. ファイルシステムのゼロトラスト
ポリシーで許可された場所に書き込み、その後 `/etc`、`/usr`、`/` への書き込みを試みます。

=== 6. 認証情報のセキュリティー
サンドボックス内でキーを出力し、境界を経由してキーを使用し、さらに別のエンドポイントに対してキーを試します。

=== 7. ZTVP 統合
Vault をバックエンドとする ExternalSecret、ClusterSPIFFEID、ACS Central、Keycloak クライアントを読み取ります。

=== 8. ユーザー認証
Keycloak ユーザーを作成し、ゲートウェイクライアント用のトークンを要求して、そのクレームをデコードします。

=== 9. 動的ポリシー
実行中のサンドボックスで `pypi.org` を許可し、機能することを検証してから取り消します。

== 解釈上の注意点

* このラボで示すのは、1 つのポリシーを持つ 1 つのサンドボックスです。境界のオーバーヘッドや、負荷がかかったときの動作は測定しません。
* ラボをすぐに開始できるように、デモのゲートウェイは認証されていない CLI 呼び出しを受け付けます。モジュール 8 では
  OIDC がどのように構成されているかを示しますが、匿名の呼び出し元を拒否するゲートウェイを示すものではありません。
* サンドボックスはクラスター上の Pod として実行されます。コンテナーエスケープは、このラボのテスト範囲外です。
* OpenShell、Pi エージェントのイメージ、およびデモチャートはアップストリームおよびコミュニティーのコンポーネントであり、Red Hat がサポートする製品ではありません。xref:91-reference.adoc[技術リファレンス] を参照してください。
