= 아키텍처와 제어 경계
:navtitle: 아키텍처와 제어 경계

이 페이지에는 명령이 없습니다. 이후의 모든 결과를 이해할 수 있도록 각 구성 요소가 어떻게 맞물리는지 설명합니다.

== 제어 질문

각 모듈은 여러분이 직접 수집한 증거로 다음 질문 중 하나에 답합니다.

* *에이전트가 승인하지 않은 호스트로 데이터를 보낼 수 있는가?* (모듈 4)
* *에이전트가 root 권한으로도 작업 디렉터리 밖의 파일을 읽거나 변경할 수 있는가?* (모듈 5)
* *에이전트가 LLM API 키를 보거나, 출력하거나, 유출할 수 있는가?* (모듈 6)
* *키는 어디에 저장되고, 누가 동기화하며, 워크로드는 어떻게 식별되는가?* (모듈 7)
* *게이트웨이 접근에 실제 사용자 ID를 요구할 수 있는가?* (모듈 8)
* *에이전트를 다시 배포하지 않고도 에이전트가 접속할 수 있는 대상을 변경할 수 있는가?* (모듈 9)

== 스택

[cols="1,2,3",options="header"]
|===
| 계층 | 구성 요소 | 역할

| 플랫폼
| OpenShift(AWS 기반 단일 노드)
| 모든 것을 실행합니다. Developer Catalog, Route, Web Terminal

| ZTVP
| HashiCorp Vault (`vault`)
| MaaS API 키를 ``secret/hub/infra/openshell/maas``에 암호화하여 저장합니다

| ZTVP
| External Secrets Operator (`external-secrets-operator`)
| 게이트웨이를 위해 Vault의 키를 Kubernetes 시크릿으로 동기화합니다

| ZTVP
| Zero Trust Workload Identity Manager, SPIFFE/SPIRE (`zero-trust-workload-identity-manager`)
| OpenShell 파드에 워크로드 ID(SVID)를 발급합니다

| ZTVP
| Advanced Cluster Security (`stackrox`)
| 이미지를 스캔하고 배포 및 런타임 정책을 강제 적용합니다

| ZTVP
| Red Hat build of Keycloak (`keycloak-system`)
| 사용자를 인증하고 게이트웨이 클라이언트용 OIDC 토큰을 발급합니다

| 애플리케이션
| OpenShell 게이트웨이 (`openshell-system`)
| CLI용 gRPC API입니다. 샌드박스, 프로바이더, 정책을 관리합니다

| 애플리케이션
| OpenShell 수퍼바이저
| 에이전트의 프로세스 트리 밖에서 실행됩니다. 네트워크 경계를 강제 적용하고 리졸버 토큰을 실제 자격 증명으로 교체합니다

| 애플리케이션
| 샌드박스 `pi-agent-demo`
| 네트워크 정책과 Landlock 정책 아래에서 Pi 에이전트가 실행되는 컨테이너입니다
|===

== 반드시 이해해야 할 한 가지 차이

Kubernetes NetworkPolicy는 어떤 **파드**가 어떤 주소와 통신할 수 있는지를 결정합니다. OpenShell 네트워크
정책은 **샌드박스 안의 어떤 프로그램**이 어떤 **호스트 이름**에 접속할 수 있는지를 결정합니다. ``curl``은
MaaS API를 호출할 수 있고, ``npm``은 npm 레지스트리를 호출할 수 있으며, 그 외에는 어떤 것도 어디에도 접속할 수 없습니다.
샌드박스는 목록에 없는 모든 호스트를 자리 표시자(placeholder) 주소로 해석하고 수퍼바이저가 연결을 거부하므로, 거부된
호출은 시간 초과를 기다리지 않고 수 밀리초 안에 실패합니다.

자격 증명도 같은 방식으로 동작합니다. 샌드박스 안에서 ``MAAS_API_KEY``는 리졸버 토큰입니다. 에이전트가 접근할 수 없는
곳에 있는 수퍼바이저만이 이 토큰을 실제 키로 교체하며, 그것도 프로바이더가 바인딩된 엔드포인트로 가는 요청에 대해서만
교체합니다.

요청 경로는 다음과 같습니다.

[cols="1,3",options="header"]
|===
| 홉 | 동작

| 1. CLI → 게이트웨이 Service
| ``openshell sandbox exec``가 게이트웨이의 클러스터 내부 Service로 HTTPS를 통해 gRPC를 전송합니다(공개 Route는 없으며, NetworkPolicy는 랩 네임스페이스와 Web Terminal 네임스페이스만 허용합니다)
| 2. 게이트웨이
| 게이트웨이가 샌드박스를 찾아 명령을 전달합니다
| 3. 게이트웨이 → 수퍼바이저 → 샌드박스
| 수퍼바이저가 정책을 적용한 상태로 샌드박스 안에서 명령을 실행합니다
| 4. 샌드박스 → 경계
| 모든 아웃바운드 연결은 호스트 및 바이너리 허용 목록과 대조하여 검사됩니다
| 5. 경계 → MaaS
| 허용된 MaaS 호출의 경우, 리졸버 토큰이 Vault에서 가져온 실제 키로 교체됩니다
|===

== 랩 진행 순서

=== 1. 카탈로그에서 OpenShell 배포
차트 리포지토리를 등록하고, MaaS 키로 릴리스를 설치한 다음, 훅이 Vault에 값을 시드하고,
샌드박스를 생성하고, Keycloak 클라이언트를 등록하는 과정을 확인합니다.

=== 2. OpenShell CLI 연결
CLI가 게이트웨이 Service를 가리키도록 설정하고, 샌드박스 목록을 조회한 다음, 외부에서는 누구도 게이트웨이에 접근할 수 없음을 확인합니다.

=== 3. Pi를 이용한 AI 에이전트 코딩
Pi에게 스크립트와 작은 REST API를 요청한 다음, 샌드박스 안에서 실행합니다.

=== 4. 네트워크 제로 트러스트
허용된 호스트와 목록에 없는 호스트를 호출하고, 결과와 소요 시간을 비교합니다.

=== 5. 파일 시스템 제로 트러스트
정책이 허용하는 위치에 쓴 다음, `/etc`, `/usr`, ``/``에 쓰기를 시도합니다.

=== 6. 자격 증명 보안
샌드박스 안에서 키를 출력하고, 경계를 통해 사용한 다음, 다른 엔드포인트에 대해 사용해 봅니다.

=== 7. ZTVP 통합
Vault 기반 ExternalSecret, ClusterSPIFFEID, ACS Central, Keycloak 클라이언트를 확인합니다.

=== 8. 사용자 인증
Keycloak 사용자를 생성하고, 게이트웨이 클라이언트용 토큰을 요청한 다음, 클레임을 디코딩합니다.

=== 9. 동적 정책
실행 중인 샌드박스에서 ``pypi.org``를 허용하고, 동작함을 증명한 다음, 철회합니다.

== 해석 시 유의 사항

* 이 랩은 하나의 정책을 가진 하나의 샌드박스를 보여 줍니다. 경계의 오버헤드나 부하 상황에서의 동작은
  측정하지 않습니다.
* 랩을 빠르게 시작할 수 있도록 데모 게이트웨이는 인증되지 않은 CLI 호출을 허용합니다. 모듈 8은 OIDC가
  어떻게 연결되는지를 보여 주며, 익명 호출자를 거부하는 게이트웨이를 보여 주지는 않습니다.
* 샌드박스는 클러스터에서 파드로 실행됩니다. 컨테이너 탈출은 이 랩의 테스트 범위에 포함되지 않습니다.
* OpenShell, Pi 에이전트 이미지, 데모 차트는 업스트림 및 커뮤니티 구성 요소이며 Red Hat이 지원하는 제품이
  아닙니다. xref:91-reference.adoc[기술 참조]를 확인하십시오.

xref:02-details.adoc[사전 요구 사항과 환경]으로 계속 진행하십시오.
