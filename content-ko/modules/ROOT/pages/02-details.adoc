= 사전 요구 사항과 환경
:navtitle: 사전 요구 사항과 환경

== 필요한 사항

[cols="1,2",options="header"]
|===
| 대상 | 필요한 사항

| 모든 참가자
| 브라우저, OpenShift 사용자 ``{lab_user}``와 그 비밀번호, Red Hat MaaS API 키(`sk-…`)

| 진행자
| xref:modules::92-facilitator-guide.adoc[진행자 가이드(영어)]에 따라 준비된 클러스터
|===

진행자가 제공하는 항목:

* OpenShift 웹 콘솔 URL(아래 접속 정보 표에 표시됨).
* 이 전용 클러스터에서 cluster-admin 권한을 가진 OpenShift 사용자 ``{lab_user}``의 비밀번호.
* 모델 ``{maas_model}``을 사용할 수 있는 MaaS API 키.

클러스터에는 이미 Zero Trust Validated Pattern(Vault, External Secrets Operator, Keycloak,
SPIFFE/SPIRE, Advanced Cluster Security)과 OpenShift Web Terminal이 실행 중입니다. 이들 중 어느 것도 직접 배포하지 않습니다.

IMPORTANT: 이 랩은 사용자 정의 리소스 정의(CRD)와 클러스터 범위의 Helm 차트 리포지토리를 설치하고,
Keycloak 관리자 시크릿을 읽습니다. 그래서 cluster-admin 사용자를 사용하며, Showroom 페이지에
내장 터미널이 없는 것도 이 때문입니다. Showroom URL을 가진 누구나 그 터미널을 사용할 수 있기 때문입니다.

== Web Terminal 열기

이 랩의 모든 명령은 OpenShift Web Terminal에서 실행합니다. Web Terminal은 브라우저에서 동작하는 셸이며
이미 본인 계정으로 로그인되어 있습니다.

. 콘솔을 엽니다: link:https://console-openshift-console.{cluster_domain}/k8s/cluster/projects[console-openshift-console.{cluster_domain}^].
. 로그인 페이지에서 **openshell-lab-htpasswd**를 클릭한 다음, ``{lab_user}``로 로그인합니다.
. 마스트헤드에서 *Command line terminal*(명령줄 터미널) 아이콘(`>_`)을 클릭합니다.
. *Initialize terminal*(터미널 초기화)에서 *Project*(프로젝트)를 ``openshift-terminal``로 그대로 두고 *Start*(시작)를 클릭합니다.

예상 결과: **OpenShift command line terminal**이라는 제목의 패널이 열리고 프롬프트 ``bash-5.1 ~ $``가 표시됩니다.

NOTE: Web Terminal은 일정 시간 동안 활동이 없으면 중지되며 홈 디렉터리는 유지되지 않습니다. 터미널이
다시 시작되면 아래 설정 블록을 다시 실행하십시오. 다시 실행해도 안전합니다. 또한 이 클러스터의 컴플라이언스
설정에 따라 10분 동안 활동이 없으면 로그인이 만료됩니다. ``oc``가 ``Unauthorized``를 보고하면 터미널 패널을 닫고
마스트헤드에서 다시 연 다음(필요하면 먼저 콘솔 페이지를 새로 고침), 설정 블록을 실행하십시오.

== 터미널 설정

이 블록은 OpenShell CLI {openshell_version}(게이트웨이와 같은 버전)을 설치하고, 체크섬을 검증하고,
CLI가 게이트웨이의 클러스터 내부 Service를 가리키도록 설정하며(Web Terminal은 클러스터 내부에서 실행됨),
차트 리포지토리를 Helm에 추가합니다.

[source,bash,role="execute",subs="attributes+"]
----
mkdir -p ~/bin && cd /tmp
curl -fsSLO https://github.com/NVIDIA/OpenShell/releases/download/v{openshell_version}/openshell-x86_64-unknown-linux-musl.tar.gz
curl -fsSLO https://github.com/NVIDIA/OpenShell/releases/download/v{openshell_version}/openshell-checksums-sha256.txt
grep ' openshell-x86_64-unknown-linux-musl.tar.gz$' openshell-checksums-sha256.txt | sha256sum -c - \
  && tar -xzf openshell-x86_64-unknown-linux-musl.tar.gz -C ~/bin openshell; cd ~
cat > ~/.openshell-lab.env <<'ENV'
export PATH=$HOME/bin:$PATH
export OPENSHELL_GATEWAY_ENDPOINT=https://{release_name}.{lab_namespace}.svc.cluster.local:8080
export OPENSHELL_GATEWAY_INSECURE=true
ENV
grep -q openshell-lab.env ~/.bashrc || echo 'source ~/.openshell-lab.env' >> ~/.bashrc
source ~/.openshell-lab.env
helm repo add openshell-ztm-demo {chart_repo_url} --force-update >/dev/null
openshell --version
----

예상 결과: `openshell-x86_64-unknown-linux-musl.tar.gz: OK`(다운로드한 파일이 게시된 체크섬과
일치함), 그다음 ``openshell {openshell_version}``이 표시됩니다. 아카이브는 체크섬이 일치할 때만 압축이 해제됩니다.
일치하지 않으면 ``FAILED``가 표시되고 `openshell` 바이너리는 생성되지 않습니다.

== 사전 점검 실행

[source,bash,role="execute",subs="attributes+"]
----
oc whoami
oc auth can-i create customresourcedefinitions
oc auth can-i get secrets -n keycloak-system
oc get pods -n vault vault-0 --no-headers
oc get clustersecretstore vault-backend --no-headers
----

예상 결과: `{lab_user}`, 그다음 ``yes``가 두 번 표시되고(클러스터 범위에 관한 CRD 경고는 무시해도 됩니다),
``vault-0``이 ``1/1 Running``으로, ``vault-backend``가 `Valid` 및 ``True``로 표시됩니다. Vault와 ClusterSecretStore는
차트가 연결되는 ZTVP 서비스입니다. 둘 중 하나라도 없으면 중단하고 진행자에게 알리십시오.
